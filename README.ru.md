# WCAM — встраивание и чтение водяного знака, устойчивого к печати и съёмке

[English version](README.md)

Реализация метода Pramila, Keskinarkaus, Seppänen, «Increasing the capturing
angle in print-cam robust watermarking» (Journal of Systems and Software 135,
2018), с опорой на их же более раннюю работу в SIViP 6 (2012), где изложены
детали встраивания.

Сообщение из 32 бит кодируется углами поворота периодического узора в
шестнадцати блоках изображения. Отпечаток можно сфотографировать под углом,
и сообщение прочитается обратно.

## Установка

    python -m venv .venv
    .venv/bin/pip install -r requirements.txt

Нужен Python 3.10 или новее; проверено на 3.14.7.

## Три команды

### Встроить сообщение в изображение

    python embed_cli.py sample_images/peppers.png --payload deadbeef

Получится `out/peppers_wm.png` — этот файл и надо печатать или показывать на экране.
Рядом лягут `out/peppers_wm_core.png` (без рамки) и `out/peppers_wm.json` с нагрузкой и
пятнадцатью встроенными углами, по которым потом можно проверить чтение.
Без `--payload` нагрузка берётся случайная. Ключи `--delta1` и `--delta2`
задают силу встраивания, `--out` — имя файлов.

Узор строится повторением маленькой псевдослучайной плитки. Своя подаётся
ключом `--tile`:

    python embed_cli.py sample_images/peppers.png --tile tile_demo.npy
    python embed_cli.py sample_images/peppers.png --tile tile22_fixed.npy

Годится `.npy` с числами либо картинка, где светлое читается как +1, а тёмное
как −1. Размер любой, не обязательно 28×7. Больше ничего при этом не меняется:
поворот, сила встраивания, порог заметности остаются те же.

В комплекте две плитки: `tile22_fixed.npy` — восстановленная из рисунков
авторов, `tile_demo.npy` — пример произвольного размера 12×5.

Читающей стороне плитка не нужна и не сообщается: угол решётки измеряется
автокорреляцией, содержимое плитки на это не влияет. Поэтому её можно менять,
не трогая `process_photo.py`.

Ключ `--mode` выбирает, как воспроизводить изображения авторов:
`plain` (по умолчанию) — наш узор, билинейный поворот по ур. 14;
`papercalib` и `papermode` — их плитка с поворотом ближайшим соседом,
с калибровкой амплитуды и без.

### Прочитать сообщение с одной фотографии

    python process_photo.py out/peppers_wm.png

Выпрямляет снимок по рамке и читает углы блоков. Печатает долю ошибочных
блоков до исправления ошибок и сравнивает прочитанную нагрузку с той, что
лежит в метаданных.

Метаданные необязательны — сообщение читается из самой фотографии, эталон
нужен только чтобы сверить ответ. Файл ищется сам: рядом с фотографией по её
имени, затем в `out/`. Если его нет вовсе, чтение всё равно состоится:

    python process_photo.py снимок.jpg
    decoded payload: deadbeef
    (метаданные не переданы -- сверить не с чем; нагрузка прошла проверку пересборкой)

Проверка пересборкой нужна вот зачем. Рид — Соломон не сообщает о своём
провале: получив больше ошибок, чем может исправить, он всё равно выдаёт
правдоподобную нагрузку. Поэтому ответ заново кодируется и сравнивается с
измеренными углами — настоящее исправление расходится с ними не больше чем
в трёх местах, выдуманное в куда большем. Без эталона это единственное, что
отличает прочитанное сообщение от выдуманного.

Запуск без аргументов печатает подсказку.

### Прочитать сообщение с фокус-стека

    python _run_real_stack.py <каталог съёмки>

Полный конвейер разделов 3.1–3.8: карты резкости, отбор кадров, приведение
масштаба, совмещение по AKAZE, склейка, выпрямление, чтение блоков. На вход
идёт каталог, снятый приложением для iPhone: внутри `stack.bin` с кадрами и
`notes.txt` с тем, что приложение показало на экране. Запуск без аргументов
печатает подсказку.

## HEIC

iPhone снимает в HEIC, а OpenCV этот формат не читает. Скрипты обходят это
сами: если установлен `pillow-heif`, берут его, иначе обращаются к `heif-dec`
из libheif. Так что снимок можно подавать как есть:

    python embed_cli.py IMG_2399.HEIC --payload cafe1234
    python process_photo.py out/IMG_2399_wm.png

Если ни того ни другого в системе нет, скрипт скажет об этом прямо и
предложит перевести файл в PNG или JPEG.

### Разобрать фокус-стек на кадры

    python dump_stack.py <каталог съёмки>

Записывает каждый кадр стека отдельным PNG в `out/<имя съёмки>/` и печатает
таблицу: номер кадра, положение линзы, расстояние наводки. Полезно, когда
нужно посмотреть глазами, что именно сняла камера, — например почему на одном
кадре лист резок, а на другом нет. Вторым аргументом можно задать другой
каталог. Запуск без аргументов печатает подсказку.

## Куда всё складывается

Всё порождаемое идёт в каталог `out/` рядом со скриптами. Если указать имя
с путём — например `--out /tmp/лист` — он будет соблюдён как есть.

## Формат stack.bin

Заголовок — четыре 32-битных целых, little-endian: число кадров, ширина,
высота, множитель яркости. Дальше подряд кадры, по `ширина × высота`
беззнаковых 16-битных целых на кадр, построчно. Значение пикселя — яркость,
умноженная на множитель (обычно 64), один канал.

## Из чего что состоит

| файл | что делает |
| --- | --- |
| `pattern.py` | псевдослучайная плитка 7×28 и её поворот (раздел 2) |
| `jnd.py` | карта порога заметности, по Chou и Li с правкой авторов |
| `preprocess.py` | винеровская фильтрация перед встраиванием (ур. 1) |
| `codec.py` | RS(15,8) над GF(16), код Грея, углы (ур. 11) |
| `embedder.py` | собственно встраивание (ур. 15) |
| `sharpness.py` | карты резкости фокус-стека (3.2) |
| `substack.py` | отбор кадров (3.3) |
| `reconfigure.py` | приведение масштаба (3.4) |
| `register.py` | совмещение по AKAZE (3.5) |
| `blend.py` | склейка (3.6) |
| `rectify.py` | поиск рамки и выпрямление (3.7) |
| `extractor.py` | измерение углов блоков (3.8) |
| `capture.py`, `degrade.py` | синтетическая модель печати и съёмки |
| `imread.py` | чтение изображений, включая HEIC |
| `dump_stack.py` | разбор stack.bin на отдельные кадры |

## Пример данных

`sample_images/` — тестовые изображения Baboon и Peppers. `stack.bin` и
`notes.txt` — настоящая съёмка фокус-стека напечатанного листа с водяным
знаком; её можно сразу прочитать: `python _run_real_stack.py .`
